Every game runs one loop

Action

The player makes a choice.

Response

The rules change the world's state.

Feedback

The player sees what happened, at once.

…and the feedback sets up the next choice.

Step 1 · Action: give the player a dilemma

No dilemma

"Press Launch to launch the rocket."

There's only one sensible move, so there's nothing to decide.

A real trade-off

"Launch now in bad weather, or wait a day and lose the orbital window?"

Both options cost something. That's a choice.

Step 2 · Response: rules anyone can read

A rule is one line of cause and effect

Same choice, same result, every time. No dice, no black-box AI.

If the player can't predict the rule, they can't plan, so they can't really choose.

Rule card

  • Heaters on → power −25, warmth +25
  • Every sol in the storm → warmth −20, oxygen −20
  • Any meter hits 0 → mission over

Step 3 · Feedback: show it within a second

Colour

Green is safe. Yellow is a warning. Red is trouble. No reading needed.

Sound

A beep on every change, an alarm before failure.

Numbers

Show the exact change: "oxygen −20". Players learn the rules from it.

Turn a challenge into variables

The challenge text

"Design a base that keeps a crew alive at the lunar south pole: power is limited during the long night, temperatures drop sharply, and oxygen must be produced on site."

Example written for this workshop.

What to pull out

  • Resources that run out: power, oxygen
  • Threats that push back: cold, the long night
  • The goal: survive until sunrise

Keep it to 2–4 variables

1 variable

Too shallow. There's nothing to trade off, so it's a quiz.

3 variables

The sweet spot. Enough tension for real choices, small enough to finish in 48 hours.

5+ variables

Scope death. You'll spend Saturday balancing and ship nothing Sunday.

Too heavy to fly?

Get the heaviest satellite to orbit. Too little fuel: you fall back. Too much: stuck on the pad.

Three must-haves. Then one extra.

Every game needs

  • Choices: a real dilemma
  • Challenge: never enough to go around, like Eco-Metropolis
  • Feedback: see what broke, like PureFlow

Pick ONE extra

  • Story, like TerraTales
  • Characters, like Henry in Zumorroda-X
  • Mystery: data reveals a clue
  • Puzzle: a combination to crack

Fun is the result, not an ingredient.

Four ideas that kill a 48-hour project

Open worlds

Multiplayer

Custom 3D pipelines

Realistic physics engines

Instead: one screen, one loop, one finished level.

Use the tool you already know

Good picks for 48 hours

  • Browser (HTML + canvas): judges click a link and play
  • Godot: light, free, fast 2D
  • Three.js: 3D in the browser, like the capsule and rocket scenes in this deck
  • Unity: only if your team already knows it

One rule: track your variables in one shared doc.

Every number and every rule, in one place the whole team can edit.

AI: a fast copilot, a bad scientist

Use AI for

  • Writing state and rule code
  • Balancing numbers so it's not too easy
  • Placeholder art and sounds

Never for

  • Inventing the science
  • Numbers you can't trace to a NASA source

Check every number it gives you.

Got an AI agent?

Claude Code, Cursor, Antigravity, Codex: it opens your project, runs the game, reads the error and fixes it. You still review every change it makes.

The one-minute spec

1 · Goal (one sentence)

Keep the lunar crew alive through a 14-day night. One action per day.

2 · Three variables

  • Battery: starts 100 kWh, −2 per day
  • Heat: starts +10 °C, −6 per day, safe above −10
  • Oxygen: starts 80%, −10% per day

3 · Two decisions

  • Run heaters: heat +12, battery −8
  • Run oxygen recycler: oxygen +15, battery −8

4 · Rule table

  • Battery 0 → machines off, heat −10 per day
  • Heat below −20 for 3 days → mission lost
  • Oxygen 0 → mission lost

5 · End state

Survive day 14 → crew survives.

  • Give feedback within a second
  • Simplify the science, openly
